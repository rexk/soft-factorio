Retro: the v1 build stopped to ask leave 11 times

Date: 2026-11-05Author: the build session (Claude Code)Status: fixes landed, verification belowSource: this build's session history and eval results

Of 19 questions this build put to Rex, 11 asked leave for things the kickoff had already settled: commit, push, or start the next stage. The factory now tells agents to carry approved work to its finish line, and this repository says so for its own sessions.

Why it kept stopping

  • C1. The session's default won. Claude Code's default is to commit or push only when asked. The kickoff named the finish line and the checkpoints, but nothing said in so many words that everything else was approved, so each stage ended on a question.
  • C2. A go-ahead button at every turn end. Every stage ended on a question with a "Commit and push" or "Start X" button, where it could have reported progress and kept going.
  • C3. Your settings ask before every push. ~/.claude/settings.json lists Bash(git push:*) under ask, so a push prompts whatever the session decides (outside auto mode).
  • C4. The factory taught a gate but no follow-through. The rules block said to check intent before building, and nothing about what happens after approval. The eval agents didn't ask leave, because create-pr opens pull requests without asking, but nothing told them to keep going from one stage to the next.
